# LIUO Tunnel rules

- Modify project files only here; IAP and demo are read-only provenance sources.
- Inspect branch and worktree before edits. Preserve user changes. No extra branches or worktrees, history rewriting, or broad process cleanup.
- Stage only task files; commit checked logical changes. Formal live evidence binds a clean committed revision.
- Phase two uses original GPU VGICP factors (CPU is an explicit diagnostic reference), IMU and raw UWB in the same fixed-lag X/V/B graph. Surveyed-map uncertainty uses persistent A variables with one correlated map prior; oracle anchors are exact constants. UWB callbacks validate/enqueue; only the estimator update mutates the graph. No predicted-pose priors, GNSS, clock states, planning, or duplicate motion observations.
- Vehicle truth belongs only to simulation and evaluation. Never subscribe to truth in the estimator or constrain it to the rail. Explicitly labeled oracle anchor constants are permitted diagnostics; surveyed maps must carry their external uncertainty and provenance. Do not infer anchor coordinates from IDs. Phase-three unknown-anchor calibration and map reuse are now in scope under docs/phase3_requirements.md; initial self-calibration must not load surveyed/oracle anchor coordinates or derive them from simulator spacing/order.
- New abstractions, states and weighting need a reproduced problem. Resolve the first violated invariant, without silent fallback or weakened acceptance.
- Follow docs/spec/deployment_initialization_contract.md (user-confirmed 2026-10-22): arbitrary starts inside the tunnel, including aerial platforms; stationary startup and known sensor extrinsics are available, but no fixed vehicle height, surveyed start pose or heading. Real observed/registered tunnel interior geometry and signed anchor lateral offsets are allowed with explicit frames and uncertainty. Anchor heights and first-run order are unknown; rough installation heights are initial guesses only. Do not turn simulator geometry or a 360-degree lidar FOV into a global pose prior.
- Coordinate frames, units, timestamps and covariances are contracts; update callers and meaningful tests together.
- One LIUO_RUN_DIR per run; shared resolver only. Artifacts live in runtime, profiling, export, metadata. ROS_LOG_DIR is runtime/ros. Owner alone finalizes the atomic manifest. Preserve failures, active/protected runs and external outputs.
- README describes commands; docs/spec contains contracts; handbook describes phase scope. Record tests and evidence honestly. Zero exit and RViz are not acceptance.
- Retain copied licenses and provenance. Use the provided 2-space/180-column formatter.
- GPU requires driver/device preflight and separate evidence; CPU success never implies GPU success. Snapshot does not validate rolling/deskewing.

- Phase-two scope was explicitly revised by the user on 2026-10-22: representative initialization, one frozen full-route ON/OFF pair, and existing 5 s/20 s outages. Accuracy numbers (including 0.30 m RMSE, axial and attitude limits) are reference targets, never phase-two completion gates; ten seeds, full fault matrix and strict statistical consistency are deferred. Preserve historical failures. Completion requires demonstrated effectiveness and honest initialization/status, not merely beating failed OFF. A run PASS only covers its explicit checks, not stage acceptance. Failure of one experiment or geometry-association route means update the approach and continue independent authorized work, not end the Goal. Do not require new user permission for routine algorithm choices, implementation or targeted validation; report a genuine overall blocker only under the active Goal's blocking rules.
- Phase two is delivered only in the representative scope of docs/phase2_representative_results.md. Preserve baseline 7d9a792. Phase three follows docs/phase3_requirements.md: unknown-anchor joint estimation, export of correlated map/installation information, and an independent map-reuse run. No fixed accuracy target, full seed/fault matrix or rolling/real-hardware certification is required for phase-three completion. Do not duplicate first-run installation/range information on reload or reuse a previous vehicle pose/bias as a new start prior. The present documentation task does not itself start a Goal; use docs/phase3_goal_prompt.md when requested.
