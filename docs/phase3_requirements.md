# 第三阶段任务需求：未知基站自标定与独立地图复用

日期：2026-10-22（北京时间）。状态：持续开发中，局部自标定与独立短程复用已有实测，阶段尚未验收；证据见phase3_representative_results.md。
本需求依据用户确认的下一阶段范围，覆盖 [handbook](development_handbook.md) 中原第三阶段的完整矩阵、rolling 和全面验收要求。启动文本见 [第三阶段 Goal prompt](phase3_goal_prompt.md)。

## 1. 目标与基线

**在不知道基站纵向位置、高度和前后顺序的首次运行中，联合估计机器人与基站，保存具有明确不确定度和有效范围的地图；在独立第二次运行中，从不同位置或朝向启动，利用这份地图完成代表性定位。**

主线是证明“未知固定基站能够被联合标定并成为可复用的定位依据”，不是输出一份坐标 JSON，也不是完成全部产品认证。

开发基线为 `7d9a792`，第二阶段最终生产证据绑定 `db1c1ad`。开始时核查实际 HEAD 和工作树，不回退新增工作。第二阶段在缩小后的代表性范围已交付，见 [交付报告](phase2_representative_results.md)：

- 原始 GPU VGICP、IMU、TA/AA 在同一图；有限候选初始化、地图相关误差、连续墙面观测及日志/回放可复用。
- 已验证七站直隧道、snapshot、一个种子的三个内部初始化案例及 200–2350 m 路线。
- 正常轴向/横向误差较小，高度仍弱；20 s 断流漂移、恢复认证及后验过度自信未解决。本阶段不以修复这些问题的全部表现为前置任务，只修复阻碍自标定/复用的实际依赖。

冻结并保留第二阶段的配置、输入和失败记录；不得把自标定改动后的行为追溯成第二阶段已验证成果。

## 2. 输入边界与禁止的信息

现场约束以 [部署与初始化合同](spec/deployment_initialization_contract.md) 为准。

| 首次自标定可用 | 不可作为首次估计器输入 |
|---|---|
| 原始点云、IMU、TA/AA 及设备 ID | surveyed/oracle 基站坐标、坐标先验、精确基站高度 |
| 已标定 LiDAR/IMU/UWB 外参、静止启动 | 机器人真实起点、真实航向、固定离地高度、真值轨道 |
| 带来源/参考系/误差的墙侧及有符号横向安装偏距 | 由 ID、文件排序、仿真布局或 400 m 间距推断纵向位置/顺序 |
| 仅作优化初值的粗相对安装高度 | 给该初值随手赋予方差，充当独立高度测量 |
| 实际观测的局部墙面、地面、顶板及可验证关联 | 模拟器精确截面、全程中心线、地图地面/顶板真值 |

基站静止；横向偏距不是完整三维坐标。初始未知前后顺序可由估计轨迹/地图推断，但不得作为新独立测量重复入图。左右符号需要一致的参考正方向，不能从机器人朝向暗得绝对 yaw。

保留现有七站/400 m 测试世界、任意连续 1 km 至多三站、800 m 真实三维通信上限、LOS 和 σ=0.10 m 测距噪声。密度和间距是部署/模拟器条件，不是可供自标定后端读取的坐标尺。不得为显示 AA 有益而缩短量程、增加基站或改变噪声。

第二阶段的模拟安装测量可按其声明来源和相关误差复用；共同直线参考是本次代表性场景假设，不外推弯道。安装数据和已知地图坐标目前放在同一文件时，应拆分合法的安装输入，首次自标定不能先读入全部坐标再声称没有使用。仿真生成端和离线评估端可持有真值，估计器不得订阅、加载或按 ID 重建它。

## 3. 三个连贯开发步骤

### 步骤一：未知基站进入原始联合图

保持完整机器人 X/V/B 和基站 Point3 状态，不退回固定横向/高度的一维后端，也不把 LIO 输出位姿当作独立观测。

- 新建明确的自标定模式，与已知地图模式分离；未观测基站不凭空赋予可靠坐标。候选、待定、已入图、失效状态可用现有机制实现，不要求额外通用框架。
- 依据实际运动和 TA/AA、安装信息延迟初始化；处理有限多解和局部弱方向。第二阶段依赖已知三站坐标的镜像初值算法不能直接冒充未知基站初始化。
- 首轮以初始位置为原点、以声明的 yaw 约定固定规范，重力来自 IMU。规范固定只去除坐标任意性，不提供世界位置/航向或基站高度。
- 原始测距进入与 VGICP/IMU 相同的图；初值、拟合摘要不重复成为观测。墙面与 VGICP 保持既有点集归属及相关性处理。
- 候选缓存和启动批次有界。需要比现有窗口更长的运动基线时，显式处理因子保留、联合边缘化或信息移交，不能把已经使用过的 LIO 轨迹当作独立真值重新三角化。
- 静态基站按既有机制保留；AA 去重和静态测距统计仍适用。安装参考变量及共享误差不能在优化中被当作无误差常量。

先在足以建立局部有效地图的小范围闭环中打通，不先铺开全程、多种子或故障矩阵。短程成功后扩展到一条预声明代表性路线；短程结果不能冒充长路线验证。

### 步骤二：导出真实可复用的地图

导出由首轮图产生的地图，不调用真值地图生成器替代。至少记录：

- schema/version、map ID、单位、坐标规范、变量顺序、有效状态和已验证适用范围；
- 基站 ID、估计均值、联合协方差或等价信息表示、弱方向/未决分支、必要的安装参考状态；
- 安装资料及误差来源、外参身份、创建 run/源码/配置身份、所吸收观测的来源；
- 未初始化、未观测或拒绝的基站及原因，不能静默删掉失败基站后宣布完整建图。

边缘化首轮车辆状态后，保留影响地图复用的联合信息。尤其第二阶段的安装参考 L、共享安装误差若被边缘化，需保证后续墙面关联不会重新假定它们独立；可保留相关状态或作有依据的联合边缘化，自主选择实现。

保存/加载后的相同局部线性化模型应有一致的代价/信息行为；需要声明的近似，做针对性对照。不能把一个多峰后验随意压成很小的单峰高斯；不能用随意加对角线掩盖不可观或让检查通过。区分可导出的调查快照与可用于复用的有效地图。弱高度不必自动否决所有用途，但“大协方差”本身也不是地图可用证据。

保存原子化、模式与外参检查、损坏/无效地图拒绝，沿用已有工程能力。旧 KnownMap 要求至少四个基站及完整坐标，属于已知地图接口假设；如妨碍合法的小范围启动，应按观测和算法依据调整，而非把它当物理定理或任意放开有效性检查。

### 步骤三：独立第二次运行定位

加载首轮导出的有效地图及其不确定度，在新的机器人会话中初始化 X/V/B。不得复用上一轮终点位姿、IMU 偏置或偷偷附带整条“真值轨迹”。

- 采用不同起点或朝向，使用独立传感器噪声；起点先登记，只进入模拟/评估端。
- 固定基站的真实物理位置和同一安装测量资料跨次保持一致；不能每次重生成安装误差再伪称同一份静态资料。新 TA/AA 噪声属于新观测。
- 地图后验只引入一次。首轮 TA/AA、安装资料、墙面等已经吸收的信息不能再次作为独立先验加入；新采集的 TA/AA/点云可以入图，但须保留与共享安装参考的正确关系。
- 使用本轮原始 UWB、LiDAR、IMU 和合法几何初始化地图内位姿，不强制地图原点起步。有限歧义未解时诚实报告，不能长期无输出却宣称复用成功。
- 在相同地图坐标系中报告机器人轨迹；首轮固定规范到模拟世界的评估变换仅由预声明初始坐标关系确定，不用全轨迹拟合。第二轮复用同一个评估变换，不能按第二轮真实起点重新对齐消除地图误差；变换只在评估端使用。

## 4. 最小验证与有效性判据

先登记路线、起点、噪声种子、比较区段及判据，然后冻结配置。最终至少包含下列小规模证据，不做笛卡尔积 campaign：

| 验证 | 最小证据 |
|---|---|
| 首轮地图确实来自未知基站联合估计 | 输入/加载审计、地图来源、在线轨迹、基站坐标/间距/弱方向及前后顺序推断；不使用真值先验 |
| 地图保存/加载正确 | 联合信息与安装参考的针对性往返测试；无效地图拒绝；旧信息不重复入图 |
| 次轮独立复用有效 | 一次不同起点或朝向、独立噪声的代表性运行；实际完成初始化并持续输出；不能只有加载成功 |
| 复用相对定位基线的作用 | 同一份第二轮原始输入，校准地图融合与 LIO-only 配对；比较分轴误差/漂移和融合自身表现，不只比较总RMSE |
| 区分地图误差与定位误差 | 在同一第二轮输入上做一次已有已知地图定位参照，或复用真正可比证据；不把该参照地图反馈给自标定/复用 |
| AA 的作用 | 同一首轮原始输入 TA-only / TA+AA 有限对照，仅禁用指定AA入图；比较地图/轨迹变化。AA无明显收益也可接受，不以“必须优于”驱动调参 |

首次建图种子与独立复用种子分别固定一个即可，不等于展开多种子 campaign。输入相同需核对内容和测量身份，不用“同seed”替代。记录主模式及对照的实际点集/因子差异，不能把系统整体改善全部归因于单一传感器。

报告轴向/横向/高度、姿态、速度误差，地图相邻间距与全局误差、初始化等待、状态分布、处理/端到端延迟、资源与队列。量程或几何导致未观测的区段明确标出；不要求从未被观测的基站凭空可用。最终代表性复用路线必须由声明的有效地图支持，不能仅验证一个微小片段却宣称整条隧道可用。

**完成标准是系统实现且有效：** 首轮地图确实估得、保存后可被独立运行使用，复用能够约束声明区段的漂移，融合自身无未解释的持续失控或灾难性跳变，弱方向和未认证状态如实披露。允许 DEGRADED，但不能靠永远不初始化、只有极少输出或关闭诊断制造通过。地图只在已验证范围和条件内标有效；可用性不由优化器退出码、可逆矩阵或一个评估PASS替代。

原0.30/0.50m位置、0.20m间距、姿态和初始化时长等数字作为参考，**不是本阶段硬门槛**。不以另一套更宽数字取代；根据实际证据评估稳定性与作用。保留数据正确性、同图耦合、实际1×实时运行、合理有界资源及诚实状态要求；沿用必要的运行保护。评估器新增模式需明确区分参考超限、运行检查、方案有效性，不能因新schema落入旧严格判据或把PASS等同阶段完成。

## 5. 明确后移的工作

本次不要求全面解决高度精度、严格统计一致性、20s断流后的平滑/自动恢复认证；不扩展十种子、完整故障矩阵、整条往返、弯道、rolling、真实Mid-360适配、完整无人机或真机部署认证。第二阶段已有失败继续披露；仅在确实阻碍本阶段主线时修复相关实现。不得通过已知地图验证替代自标定，也不新增规划/控制/多机器人任务。

## 6. 实现入口与交付物

开始时核查实际文件，不要求照搬架构：

- `packages/liuo_tunnel/apps/liuo_tunnel_node.cpp`：模式、bootstrap、X/V/B/A/L 生命周期及地图先验；当前启动先加载 KnownMap，需要分离首次合法输入路径。
- `packages/liuo_tunnel/include/liuo_tunnel/uwb/{known_map,initialization_candidates,installation_factors,range_factors}.hpp`：复用因子/导数/安装关联，扩展未知基站和保存地图接口；不要复制成另一套松融合后端。
- `packages/liuo_tunnel/config/phase2_continuous_walls*.json`：保留基线，新模式使用单独配置；实际命名由实施决定。
- `tools/run.py`、`evaluate.py`、`compare_runs.py` 和现有日志合同：扩展必要入口，不新增通用实验平台。

交付代码、必要测试、自标定/地图导出/复用配置和实际可执行命令、代表性地图及生成身份、冻结输入/结果索引，以及 `docs/phase3_representative_results.md`。大包和运行产物沿用log管理，不把所有数据提交Git。测试以受改动影响的图生命周期、信息移交、地图读取和端到端证据为主，复用未受影响的已有测试。

## 7. 持续 Goal 执行与完成

算法路线、数据结构、可逆实现修改和针对性验证均在本阶段范围内，自主推进。先给简短计划，然后实施；不要每次实验后等待用户重新授权。

每轮实验有明确假设及能改变决策的观察；同一方向连续两次未获支持，停止盲目调参并换路径，不直接结束Goal。不得无限扩充文档/探针而始终不实现主流程。缺一项辅助现场资料时继续推进独立工作，不重复索要用户已明确没有的入口位置、高度或航向。需要新增真实设备/测量承诺或改变物理条件时再询问。

只有三个步骤及必要代表性证据完成，才标记Goal complete；结论限定为“代表性仿真中首次自标定及独立地图复用有效”。单一方案失败、参考精度未达或实验结束不等于整体阻塞；真正无可推进工作时按Goal自身规则报告具体依赖及已排除路径，不伪装成功。不要把预算/时间用尽改写成已完成。
