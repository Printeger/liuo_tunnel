## 1. 目标与范围

开发一个可实际运行的新版本：保留原始 GPU VGICP、IMU、TA/AA 同图估计，在未知 Anchor 坐标条件下支持曲线隧道与 rolling LiDAR，将 AA 作为可逐步获取、长期缓存、按需更新的静态测距地图，并在**现有短直隧道和 7 km 长曲线隧道**完成代表性验证。

主线是：**原始数据接入 → 未知 Anchor 联合估计 → 静态边持久化与唯一计权 → 相关地图导出 → 独立运行复用**。两场景均加入 LIUO LIO-only 和 FAST-LIO2 对照；AA 消融、通信等价与故障验证使用有限的定向实验，不展开全组合 campaign。

用户本次明确提出新版本开发和算法验证。因此，旧场景制作任务中的“只生成场景、不修改或运行算法”不再限制本次未来开发 Goal；旧任务的报告、原始数据及历史结论仍保持原样。**本次当前会话仅编写需求书与启动 prompt；执行 prompt 后才开始开发。**

不新增现场测量承诺，不修改既有场景几何、站点布局、量程、噪声或车辆运动来制造成功。不开展实机/RF/MAC认证、完整无人机工况、十种子测试、全局道路样条估计或分布式 Anchor 优化。FAST-LIO2 为必需第三方对照；LIO-SAM 不在本轮范围内。

## 3. 修改边界与不可破坏的原则

允许在 `src/liuo_tunnel` 修改算法、初始化、点云时序处理、静态边管理、地图格式、模拟交付策略、配置、测试、运行/评估工具，以及 FAST-LIO2 的项目内构建配置和接入适配。IAP/demo、`src/nlink_parser_uwb` 及共享 `liuo_uwb_msgs` 保持只读，不复制原消息定义。

FAST-LIO2 先核查固定版本的原生 rolling 能力，再适配接入层的 snapshot 假设；必要编译/兼容补丁放在项目内受版本控制的 patch，标清上游版本和差异。不直接修改共享安装树或改变第三方估计方法来获得更好分数。

必须保留：

- 原始 GPU VGICP、IMU、原始 TA/AA 处于同一联合估计体系；不加入预测位姿伪观测，不把 LIO 输出当独立精确位姿再次融合。
- 首轮只读传感器、外参、静止启动资料、合法安装偏距及实际观测几何；不读 Anchor 世界坐标、里程顺序、道路半径/控制点、车辆起点高度或航向真值。
- 坐标规范不等于测量先验。已知宽度不提供世界轴线；贴墙偏距是横向投影，不是三维斜距。
- 回调只校验/入队，估计器更新才修改图。每份物理信息只能在显式因子或联合 prior 中计权一次。
- 未观测、弱高度、镜像、多解与丢失状态明确报告；不要求 7/18 站全部初始化，也不允许全程 pending 却宣称融合完成。
- 保留现有直线/snapshot 兼容路径及冻结证据。新曲线路径不得暗中调用全局 `l(0)` 直线候选或因子。

## 4. 功能需求与验收条目

### C01：冻结版本、配置与测试输入

盘点生产入口、两类录包合同和旧 FAST-LIO2 接入的限制，冻结 S/L 输入、运行模式、安装资料来源、误差模型、评估规范和资源预算。新增配置应明确 scan model、外参、节点表、TA/AA策略和所有 topic/QoS，不从场景 ID 推导定位坐标。

正式算法证据绑定干净提交、实际可执行文件/依赖 hash、配置和原始输入身份。使用同一最终版本完成可比主实验；确需复用较早证据时逐项证明不受后续差异影响，不能混写二进制身份。

### C02：完整 rolling 输入与运动补偿

支持长场景原生 `ring` 和相对秒 `time`，Header 为帧首、交付为帧末。明确估计状态对应帧首还是帧末、点坐标参考帧、IMU覆盖及外参方向；根据测得 IMU 和估计状态完成运动补偿。适配高速 TA 的时间插值，保持测量时刻与发布时刻分离。

禁止清零点时间、用畸变 xyz 反推已有 ring、加载真值去畸变或以 snapshot 成功替代 rolling 验证。若用固定预处理近似去畸变，明确其与状态/IMU的依赖和重线性化边界，不把派生运动作为额外独立观测；不预设必须引入连续时间样条状态。

验收含静止、非零角速度、加减速及 80 km/h 片段、时间单位/乱序/缺 IMU 覆盖拒绝、完整 L 运行；snapshot 路径有回归。真值只可用于独立误差检查。

### C03：未知 Anchor 初始化解除全局直线依赖

保留三维 `A` 和原始距离残差。用估计轨迹与原始 TA/AA 生成候选，在联合图中估计，允许延迟扩图、镜像候选和暂不可观；不得用 ID 排序、站距、固定高度或单个全局直线给曲线 Anchor 定位。

车辆惯性/点云估计不能因 Anchor 长期未初始化而无限缓存全部历史。跨窗口使用旧 TA 初始化时，必须保留所需的车辆不确定度和相关性：采用有界联合候选/有依据的信息移交，不能保留旧位姿点估计后把它当已知量重新使用 TA。原始信息在启动图、主图和边缘 prior 之间的转移有账可查。

验收包括坐标规范等变、平面镜像/弱高度、无足够几何时诚实 pending、可观后真正加入 `A`，以及 S/L 生产路径实际进展。仅取消输入 schema 校验或关闭 `continuous_installation_walls` 不算实现。

### C04：合法局部几何的条件性使用

第一选择是通用核心；如果 C03 的具体失败证据表明需要安装信息，可加入附近实际观测墙面/断面与合法偏距。必须定义关联、局部有效范围、曲率近似误差、坐标和协方差，处理与 VGICP/IMU 的共享信息。不把车辆当前切线套到远端 Anchor，不为每站创建任意滑动的自由轴，不导入全局道路真值。

该条是有触发条件的实现项：未使用时以代码/配置审计证明没有隐含直线约束；使用时必须有失败动机、针对性检验和受影响主实验。不得将必要适配写成“以后再做”而宣称主目标已完成。

### C05：静态 AA 记录合同与接入

原始 TA/AA 继续使用现有 batch。新增的静态记录至少定义网络、物理部署 epoch、规范化端点、稳定物理样本/块 ID、内容 revision、精确覆盖关系、采集来源、误差模型和有效性；交付 session/sequence 与物理身份分开。

当前 msg 无法完整表达跨重启的摘要覆盖集合时，在项目内实现最小独立静态记录类型/适配和生产入口，记录其序列化版本及 topic/QoS；不篡改共享 msg 字段。验收不能仅靠离线 JSON 单测：缓存记录必须进入真实接入、估计器和图侧审计链路。

冻结一个有限独立测量块/边作为最小可用策略；只有确证的新独立块才增加信息。禁止把均值伪装成一次新原始测距、用 revision 冒充源帧序号、从坐标后验反算 AA 再当新观测。不同块或不同边存在共同误差时，不因 ID 不同就假设独立；无可信模型的数据不参与计权。

### C06：TA/AA 时间生命周期分离

TA 保持车辆时间关联、时钟可信度及队列检查。AA 依部署有效性、物理身份和误差模型接纳，不要求车辆 bracket；普通、启动、延迟扩图入口行为一致。未知端点的静态边有界等待。

用生产回调验证：已超车辆 lag、端点已存在的 AA 真正入图；时间未知但有充分静态部署/来源证据的合法缓存可经明确合同处理；没有证据的 unknown/freshness=false 数据仍被拒绝。不得通过把旧时间改成 now 绕过检查。

### C07：唯一计权与摘要替换

沿用独立高斯摘要的 `count/weight/mean/scatter` 与 AA 残差。每边最多一个**尚未吸收部分**的显式累计因子；旧因子确实移除后才绑定替代因子索引。持久化物理身份与覆盖清单，不持久化运行时 factor index。

重复、双向报告、转发、乱序、驱动重启不新增权重；新独立块可累计；含旧块的新累计版本只能按覆盖关系替换显式旧摘要。已进入 prior 的前缀不能再次计权；无证据可拆分的累计版本明确拒绝/隔离。图更新失败不能提前标记“已融合”。

验收比较固定状态/线性化点下显式原始高斯图和摘要图的 cost、梯度、信息矩阵，包括常数项；重复 1000 次结果不变。测试要覆盖真实因子增删与审计，不只检查容器计数。

### C08：持久 Anchor 与边缘化

先保留最多 S=7、L=18 个已初始化 `A`；纯 AA 不随车辆不可见或车辆窗口滑动而丢弃，不逐帧重加。消去旧 `X/V/B` 时保留必要相关信息，记录哪些物理信息仍显式、哪些已吸收。

测试跨多窗口保留、延迟端点入图、实际 factor 槽复用及 Schur 信息移交。当前固定线性化 prior 的近似必须披露；大幅更正历史坏块不能宣称等价全历史重优化。首版不引入 Anchor 淘汰/子图冻结来扩大此问题。

### C09：可复用地图与一致检查点

新地图 schema 支持实际 `A` 及必要局部几何的联合后验，不强制 `3N+2` 全局直线。保留规范、变量顺序、线性化点、相关性、来源、有效范围、未解决分支和已吸收 AA 覆盖清单。联合 prior 与账本作为一致检查点原子保存/恢复。

加载时旧块只去重，新的独立增量才新增权重；不重新加入旧安装观测或上一轮车辆位姿/bias。旧 v1 地图保持可读性或明确迁移拒绝，不能捏造缺失的物理账本。对无账本旧地图，仅接受能证明不与旧信息重叠的新 AA，否则拒绝该 AA 融合并解释理由。

验收包括导出/加载代价与信息、非对角相关项、错误 epoch/身份/模型/schema、损坏/不完整检查点、重启后重发已吸收块，以及每场景独立地图复用运行。

### C10：时钟重置、部署变更与有效性

ROS 时钟/驱动重启不等于 Anchor 移动。已验证同一部署的静态缓存可跨车辆时间窗重建而保留；新数据集交付不能重生同一物理块。退休交付域与缓存身份有明确不同职责。

Anchor 移动、更换或 ID 重用必须改变部署有效期，停止错误融合并处理受影响的 TA/AA/安装/后验；第一版允许明确要求新地图/重建，不要求自动迁移旧稠密 prior。低频健康检查只触发复核，不靠单个残差自动移动基站或开启新 epoch。

### C11：真实可达的静态图交付与通信比较

生成器新增可选“测量块冻结＋发现/缺失/版本变化同步”策略，保留旧连续报告模式。首次到访有可发现/获取机制；重复公告不增信息；AA 测距与报告到车的 LOS 分开。物理真值仅由生成/交付模型使用，定位器只接收真正到达的记录。

分开做两类比较：

1. **信息相同的交付比较**：固定物理测量块及噪声，连续重发与缓存同步在声明检查点交付相同唯一集合，核对信息等价及交付字节/次数；不同到达顺序可能影响在线初始化和固定滞后近似，不强求逐帧轨迹相等。
2. **减少物理测距的策略比较**：冻结少量块、后续低频检查；明确测量量改变，报告资源与几何/精度代价，不冒称同信息。

旧长包中 1.2 s 快照过期合同不能被事后放宽。需要获取更老静态块时生成独立衍生交付数据并登记新合同、稳定身份与来源；不得修改原包。不能从全局 `physical_uwb.csv` 不经可达交付直接初始化机器人缓存。

### C12：完整工具接通与 FAST-LIO2

支持两场景的生成/导入、配置、回放、observer、capture、审计和评估入口；LiDAR/IMU/UWB/静态边的 topic/QoS 贯通，至少一例非默认 topic/depth 生产验证。一个运行只有一个 `/clock` owner。

现有 FAST-LIO2 runner 有非零 time 拒绝、固定旧 LiDAR topic、360 s 上限、旧外参与路径假设；配置还含 snapshot 选项。必须逐项核对并适配，不只放开时间检查。长包用原生 ring/time，短包缺 ring 时只在已验证 snapshot 合同下恢复；时间单位与输出车体坐标有独立核查。

FAST-LIO2 只使用相同原始 LiDAR/IMU及已知外参，不读 UWB、真值或 LIUO 地图；不要求其战胜 LIUO或一定成功。接入错误必须修复；排除接入问题后真实定位失败是有效对照结果，保留失败时刻、输入与输出范围。

### C13–C16：双场景、负载和最终验收

具体实验见后两节。C13 为 S 实际生产验证；C14 为 L 实际生产验证；C15 为有界资源、通信和 1×运行；C16 为完整证据、复现入口及结论范围。

## 5. 最小实验矩阵

先跑定向测试和短片段，再冻结最终输入/配置，避免每次改动重复完整矩阵。每场景先固定首轮与独立次轮两个噪声种子；不是十种子 campaign。

| 实验 | 两场景的要求 | 主要目的 |
|---|---|---|
| R0 旧入口回归 | S 的既有 360 s 新 msg 自标定/复用可先用代表片段，再按受影响范围补充；旧 snapshot/直线模式明确标记 | 保护历史能力，不算完整 S 交付 |
| S-CAL / L-CAL | 首轮未知 Anchor，运行完整既有主路线，GPU、TA＋静态 AA，导出真实估得的地图 | 主功能，不能用 surveyed/oracle 替代 |
| S-REUSE / L-REUSE | 新进程、新 IMU/LiDAR/TA 噪声、独立车辆初始化，加载 CAL 字节固定的联合地图并走完整主路线 | 真正复用；重复旧静态块不加权 |
| S-OFF / L-OFF | 与各自 REUSE 严格相同 LiDAR/IMU，LIUO LIO-only，不加载 Anchor 坐标或安装先验 | 评估整体 UWB/地图贡献 |
| S-FASTLIO / L-FASTLIO | 与各自 REUSE 相同 LiDAR/IMU，完整路线 | 第三方对照 |
| S-TA / L-TA | 与各自 CAL 相同原始输入和其余配置，禁用 AA 融合；先选有运动与真实 AA 入图的代表片段，必要时扩至全程 | 验证 AA 图侧开关与贡献，不强求 AA 改善所有指标 |
| STATIC-PAIR | S/L 各一段可达且有旧 AA 的生产回放，比较相同块集合的连续交付与缓存同步 | 唯一计权、通信收益、迟到 AA 实际入图 |
| FAULT / LOAD | 一套至少 60 s 的真实生产入口，覆盖重复/乱序、慢订阅、驱动/ROS重置、未知端点、部署冲突和容量；两种 scan model 各做受影响冒烟 | 不变量与有界资源，不要求所有故障×所有场景 |

S 主路线采用现有普通 outbound，约 540 s，实际覆盖到 2350 m；L 主路线必须覆盖 0–7000 m、两个弯道、80 km/h段及首尾静止。若某次从内部起点出发，明确其实际覆盖，不将剩余路径称为全长。

独立复用不能仅把相同传感器包换一个 run ID。L 可保持同一正常汽车路线而重新生成独立噪声；S 至少增加一个预声明的不同起点/朝向条件，允许在同一纵向起点改变横向位置或朝向以保留主路线覆盖。设置只进入生成器和离线评估，不传给定位器。静态 AA 块可以在同一部署下保持原身份并重发；新采集块必须有新物理身份及独立性依据。

首轮地图只包含实际初始化且适用的部分，未观测/未解决站点显式列出；复用在地图覆盖外继续合法 LIO 并报告状态。**本轮仍必须在两场景得到非平凡的未知 Anchor 地图和实际有效复用，L 的证据须包含曲线运动段。** 若只能得到全程未初始化、纯 LIO 或局部极短输出，任务未完成。不得为满足这条改变物理场景或偷偷使用真值。

需要区分地图误差与估计器问题时，允许增加一个标明 synthetic surveyed/oracle 的诊断参照，但不是必需全组合，也不能替代未知坐标主线。

## 6. 评价、资源与完成条件

### 6.1 评价方法

在首次正式实验前冻结阈值、数值容差、时间区间及坐标规范。已有 0.30/0.50 m 等参考精度不是新硬门槛，也不另设更宽数字把失败改成通过；数学一致性、输入身份、无重复计权、有限输出与资源边界是硬检查。

评估端可使用首次运行定义的固定规范到仿真世界的变换；地图复用继承同一地图规范，不能用第二轮真值起点或整段最佳拟合消除重定位误差。LIO/FAST-LIO2 的局部规范单独说明；如补充对齐 APE，必须与固定规范主结果分开。RPE 配合输出覆盖率报告，不把只剩成功片段的数据当全程性能。

至少输出：

- 全路线/分段轨迹、APE/RPE、世界 XYZ 与局部沿线/横向/高度误差、姿态和速度；局部道路坐标仅用于离线评估。
- 首输出与 Anchor 初始化时刻、各状态时长、未输出/失效区间、地图有效覆盖、每站与相邻距离误差、未解分支和相关不确定度。
- AA 物理图、已交付图、已入图信息分别统计；报告连通分量、去规范后的刚性/联合弱方向，区分真值条件诊断与实际估计信息。
- 接收/拒绝/缓存/入图/已吸收的物理块与权重账本，图因子数量，地图保存/复用来源一致性。
- LiDAR/IMU/TA 的时间完整性、处理和端到端延迟、实际播放速率、队列、RSS、GPU使用、磁盘及通信量。

不要求 AA 子图单独刚性，不承诺全部高度精确或严格统计一致性认证；但不能以此豁免明显错误的确定性状态、重复信息或主流程无效。融合有效性应结合自身稳定性、实际图信息和对照解释，不能只因 OFF 完全失控就称新版成功。

### 6.2 资源与运行保护

正式 LIUO S/L 主实验使用实际 GPU VGICP、1×原时间回放，不静默 CPU 降级。离线/减速运行可以辅助诊断，但不能作为 1×证据；生成器的 7×速率与定位器实时性无关。

保留或有依据地重新声明车辆窗口、候选/静态块/退休身份/输入队列容量、磁盘预留、总墙钟和无进度超时；不能无限扩大缓存或提高超时掩盖算法没有进展。AA 图规模上界按 S=7/L=18 的实际注册节点约束，持久账本采用有界块/覆盖表达，不因重传增长。

60 s 测试包含慢订阅者、正常生产消费者、逐边统计和重传压力，证明丢包不会重复计权、恢复后可补获记录；慢 observer 丢失与生产端积压分别记录。全路线检查内存/因子增长趋势，不能用 60 s 成功宣称长期无泄漏。

构建、测试、录制、回放和分析全部 `data-run -- ...`，输出在 `/home/dev/ws_iap`。每 run 一个 owner 和 `LIUO_RUN_DIR`，遵守 [运行产物合同](spec/run_artifact_contract.md)。原始任务输入不得删除或覆盖；收尾按主机保留策略退休无需再用的重复中间物，保存报告、图、摘要、可复用地图和必要复现输入，诚实登记文件可用性。

### 6.3 Goal 完成判定

必须同时满足 C01–C16：生产实现已接通，snapshot 和 rolling 均有实际证据，S/L 主路线与独立地图复用有效，FAST-LIO2 对照完成有效接入与真实结果采集，静态 AA 的迟到/缓存/更新/重启/已吸收去重经过图侧验证，资源与信息边界通过，复现和验收文档完整。

C04 未触发时可以明确写“未引入局部几何，已审计无隐含先验”，不制造无意义实现。其余必需项不得用 TODO、SKIP、record-only、旧二进制或部分路线冒充通过。允许局部退化和真实第三方失败；不允许主系统全程无效后仅凭诊断完整宣布完成。

无法在固定条件下取得主线有效性时，保留证据、继续有依据的修复；若确实需要新物理信息或改变场景，单独报告该依赖，保持对应验收未完成，不自行降低目标。普通实现选择、可逆修复与必要验证无需反复请求确认。
